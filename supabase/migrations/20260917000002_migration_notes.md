# EnglishX50 project split (2026-09-17)

EnglishX50 moved from the shared Locrativ Supabase project
(`hiqhbxxlbonlyemxuvad`) to its own project (`ewypdhyeickjdkcubsgd`).

What was copied, and how:

- Schema: `20260917000001_x50_schema.sql`, applied through the Supabase MCP.
- Auth: the 73 accounts with EnglishX50 data plus the admin account were copied
  from `auth.users` / `auth.identities` with their original ids and password
  hashes (via `dblink` from the new project), so every `user_id` in the `x50_*`
  tables stays valid and Google sign-in re-attaches to the existing identity.
- Data: all 16 `x50_*` tables, row for row. `x50_reviews.image_url` was rewritten
  to the new project host.
- Storage: the three `x50-*` buckets were copied by a temporary edge function
  (`migrate-storage`), which can be deleted once the split is verified.
- Edge functions: `EnglishX50feedback`, `transcribe`, `realtime-transcribe`,
  `audio`, `speak-turn` redeployed. `_shared/premium.ts` is bundled into each
  function as `premium.ts` on the new project.

Secrets that must be set on the new project (Edge Functions → Secrets):
`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `CLOUDFLARE_R2_ENDPOINT`,
`CLOUDFLARE_R2_BUCKET`, `CLOUDFLARE_R2_ACCESS_KEY_ID`,
`CLOUDFLARE_R2_SECRET_ACCESS_KEY`.

Hosting: set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` to the new
project's values. The old project's `x50_*` objects are left in place as a
rollback until the split has been verified in production.
